# Test plan: linux-aurora 7.2.11.aurora14-1.sr1 (Claude, on the Studio)

Packages are staged on the Mini in `~/smartroom-aurora-kernel/out/` with
`SHA256SUMS`. This build is `smartroom/test-20261117`: `smartroom/main`
plus the AQC113 receive-filter branch and the t6021 AVE branch. The
package version sorts after the installed `7.2.11.aurora14-1`. The
running release string is `7.2.11-14-1.sr1-ARCH`.

Install only on the Studio that is already on `7.2.11-14-1-ARCH`. Do not
install on the home Studio, a room Mac, or any other machine.

```
sha256sum -c SHA256SUMS
sudo pacman -U \
  linux-aurora-7.2.11.aurora14-1.sr1-aarch64.pkg.tar.zst \
  linux-aurora-headers-7.2.11.aurora14-1.sr1-aarch64.pkg.tar.zst \
  v4l2loopback-aurora-0.15.4-1.sr1-aarch64.pkg.tar.zst
sudo reboot
```

If a reboot still reports the old release, run `sudo update-m1n1` and
reboot again. The boot picker looks up device trees under
`/usr/lib/modules/*-ARCH`.

```
uname -r
# 7.2.11-14-1.sr1-ARCH
```

## AVE encoder

```
for d in /sys/class/video4linux/video*; do
  [ -e "$d" ] || continue
  echo "$(basename "$d") $(cat "$d/name")"
done
dmesg | grep -i -E 'ave|apple-ave'
```

A bound encoder is a `/dev/videoN` named `Apple AVE video encoder`.
Point ffmpeg at that node. Width must be a multiple of 16. NV12 in,
H.264 out:

```
ffmpeg -f lavfi -i testsrc=size=1280x720:rate=30 -frames:v 30 \
  -pix_fmt nv12 -c:v h264_v4l2m2m -b:v 4M /tmp/ave-smoke.h264
ls -l /tmp/ave-smoke.h264
```

If ffmpeg opens a different card, pass its `-device /dev/videoN` private
option using the node named above.

These dmesg lines are a finished observation. Copy the line into the
report and stop; do not invent firmware reservations:

- `no preloaded firmware` (Stage 2 did not attach two memory-regions)
- `unsupported firmware (text CRC --------)` (record the CRC)
- `unexpected firmware segment sizes`
- `firmware must start its DART window`
- `firmware text differs from loader CRC`
- `firmware data is not in its boot state`
- `encoding refused: firmware TEXT`

Background is in `Documentation/smartroom/ave-t6021.md`.

## Ethernet, promiscuous mode off

Find the wired profile (`nmcli -f NAME,DEVICE connection show`). Below,
`WIRED` is that profile's name on `end0`.

```
nmcli connection modify "$WIRED" 802-3-ethernet.accept-all-mac-addresses -1
nmcli connection up "$WIRED" ifname end0
ip -d link show end0
```

`ip link` must not show `PROMISC`, and `promiscuity` must be 0.

1. Unicast. From another LAN host, ping the Studio. On the Studio,
   `ping -I end0 -c 3 <gateway>` must get replies.
2. IPv6 router advertisement. This exact command, including `-p`
   (tcpdump turns promiscuous mode on without it):
   `tcpdump -p -ni end0 -c 2 icmp6 and ip6[40] == 134`
3. DHCP. Bring the wired profile down and up. A lease must arrive
   while PROMISC is off.
4. Broadcast. `arping -I end0 <gateway>` from the Studio.

Wi-Fi is the fallback if wired receive fails. Restore the shipping
workaround only in that case:

```
nmcli connection modify "$WIRED" 802-3-ethernet.accept-all-mac-addresses 1
nmcli connection up "$WIRED" ifname end0
```

Note `dmesg | grep -i atlantic` and whether PROMISC is on.
Details are in `Documentation/smartroom/aqc113-rx-filter.md`.
