Branch: `smartroom/ave-t6021`

The driver is imported from aurora-silicon `integration/aurora` commit
`145922a30cc66893ba60a4cafd16d2197876e5f6`
(`drivers/media/platform/apple/ave`). omacom/linux-aurora does not carry it.
This branch adds the t6021 match and the M2 Max device-tree nodes.

## Firmware identity

t6021 (M2 Max, j475c) is the same 6070.11.1 coprocessor generation as t8112
(M2). The image in macOS 13.5 22G74 is `AppleAVE2FW_H14C`, not t8112's
`H14G`. TEXT is `0xf0000` and DATA is `0x134000`. Both encoders share one
TEXT and each has its own DATA. The link cell is still TEXT+`0x423c`. The
identity CRC, TEXT with that cell zero, is `0x0d56db87`. Hashing H14G and
H13S the same way reproduces `0x25bfd039` and `0x460c7a7c`.

AppleAVE2 in `kernelcache.release.mac14j` formats soc-id as `t` plus a
decimal. The t6021 row is device 20 and type 17 (t8112 is 18/15, t6000 is
14/11). Boot arg `0x10000`, timebase multiplier 1, mailbox idle `0x38`, and
restoring DATA before the first start stay as on t8112. extra0 is the
power-control resource: ave1's window is `0x3dfc` bytes and neither base is
16 KiB aligned, so the variant asks for `0x3dfc` and the mapper accepts the
unaligned base.

t6000 (M1 Pro) is the previous generation and programs the timebase in
microseconds. t6041, t8140, t8142, and t6050 are the M4 / A18 / M5
coprocessor. ave1 is a second instance of this block, not a different
variant. `ave_layout_6070_11_1` has `encode_ready`. An unknown TEXT CRC
fails probe with `unsupported firmware (text CRC %08x)`.

## Device tree

Codec, mailbox, coproc, power-control and fabric follow the aurora-silicon
`t6021-peripherals` ave0/ave1 description. Each encoder has two translating
DARTs, at `*030000` and `*040000`, stream 0. That is the set t8112, t8103,
t6000 and t6001 actually wire, and the set t6030 keeps after it stops
calling the other two windows IOMMUs.

The peripherals dump also labels `*020000` and `*044000` as t8110 DARTs and
lists all four in `iommus`. Those two registers are one auxiliary aperture.
t6001 describes the same pair (`507020000` and `507044000`) as
`apple,t6000-ave-dma`; t8103 does the same; t6030 calls `*044000` a DAPF
and does not put either window in the encoder's `iommus`. On j475c,
apple-dart read `*044000` as a t8110 DART and got 385 streams (ave0) and
350 streams (ave1). `DART_T8110_PARAMS4` bits [8:0] are the stream count,
and the driver rejects anything above 256, so those nodes never probed and
the encoder had no translating domain. A count under 256 is not proof the
other window is a DART: that is the only check, and `*020000` is the first
register of this same aperture. The encoder nodes no longer reference it.

t6020 includes `t6021.dtsi` and deletes `pmgr_south`, which owns
`ps_venc1_*`, so t6020 deletes ave1, ave1's DMA aperture and ave1's DARTs.

No `memory-region` is written here. The Aurora Stage 2 loader attaches
`apple,asc-mem` / `no-map` reservations and records
`/chosen/aurora,ave-text-crc32` and `aurora,ave-data-crc32`. ave0 and ave1
share the TEXT reservation: each encoder is one `iommu-addresses` tuple,
and each reservation carries `aurora,crc32` because the DATA images differ.
Inventing physical addresses would point the driver at the wrong RAM.
Without that handoff, probe stops with `no preloaded firmware` and does not
register `/dev/video`.

## Suggested PR text

Subject: media: apple: boot the t6021 H14C AVE image

The M2 Max preloads AppleAVE2FW_H14C (6070.11.1, TEXT `0xf0000`, DATA
`0x134000`, identity CRC `0x0d56db87`). Device id 20 and type 17 come from
AppleAVE2's soc-id table. ave0 and ave1 share TEXT; each reservation has
its own `aurora,crc32`. The `*020000`/`*044000` windows are the auxiliary
DMA aperture, not encoder DARTs. The M2 Pro drops ave1 with `pmgr_south`.

## Test plan (Claude, on the Studio)

After installing `linux-aurora` `7.2.11.aurora14-1.sr1` and rebooting:

```
uname -r
# expect 7.2.11-14-1.sr1-ARCH

for d in /sys/class/video4linux/video*; do
  echo "$(basename "$d") $(cat "$d/name")"
done
dmesg | grep -i -E 'ave|apple-ave'
```

A bound encoder is a `/dev/videoN` named `Apple AVE video encoder`.
Two instances can show up. Then:

```
ffmpeg -f lavfi -i testsrc=size=1920x1080:rate=30 -frames:v 30 \
  -pix_fmt nv12 -c:v h264_v4l2m2m /tmp/ave-smoke.h264
ls -l /tmp/ave-smoke.h264
```

These dmesg lines are a completed test, not a crash to paper over. Copy
them into the report:

- `no preloaded firmware` — Stage 2 did not attach two `memory-region`s
- `unsupported firmware (text CRC --------)` — record that CRC
- `unexpected firmware segment sizes`
- `firmware must start its DART window`
- `firmware text differs from loader CRC` or `firmware data is not in its boot state`
- `encoding refused: firmware TEXT`

Width must be a multiple of 16. NV12 in, H.264 Annex B out.
